FARMDB — Updated Level & Mission Plan

The important part only: the final Normal/Data Analytics and Full Stack flow, what each path covers, and concrete mission ideas for every SQL topic.

1. Final Level Flow

The key correction: database design is part of the shared Normal/Data Analytics foundation. Full Stack begins only with the additional database-development topics that are not part of the DA core.

Normal / Data Analytics

1 Setup→2 Stock→3 Find→ 4 Plant & Cleanup→5 COUNT→6 Aggregates→ 7 HAVING→8 Filtering→9 Supply→ 10 Market→11 JOIN→12 Reports→ 13 Subqueries→14 CTE→ 15 DB Design→16 DA Final
→ FARM DATA ANALYST

Full Stack SQL

1–15 Shared Foundation→16 DA Final→ 17 Views→18 Transactions→19 Triggers→ 20 Procedures→21 Access→22 Intelligence→23 Drought
→ FARM BUSINESS OWNER

2. What Is Covered

Shared Foundation — Normal/DA + Full Stack

  • Database, tables, rows, columns and data types
  • CREATE DATABASE, USE, CREATE TABLE
  • INSERT and SELECT
  • WHERE, ORDER BY, LIMIT
  • UPDATE and DELETE
  • COUNT, SUM, AVG, MIN, MAX
  • GROUP BY and HAVING
  • AND, OR, IN, BETWEEN, LIKE
  • Dates and CASE
  • INNER, LEFT, RIGHT and FULL OUTER JOIN concept
  • Multiple JOINs, aliases, calculated columns and NULL
  • Subqueries and correlated subqueries
  • CTE / WITH
  • ALTER TABLE, ADD/DROP COLUMN, RENAME TABLE, DROP TABLE
  • PRIMARY KEY and FOREIGN KEY
  • 1:1, 1:M and M:M relationships
  • ER diagrams and normalization
  • Business analysis

Full Stack Extension

  • Views
  • Transactions, COMMIT, ROLLBACK, SAVEPOINT
  • Triggers
  • Stored procedures, parameters, variables, IF/CASE
  • GRANT and REVOKE
  • AI/data intelligence concepts
  • Final integrated business decision

3. Level → Mission Plan

Each level can contain multiple short missions. The mission is what the student actually does in the SQL terminal; the farm changes after successful validation.

#Level / TopicsPossible MissionsFarm / Result
1Farm Setup
Database, tables, data types, CREATE, USE, INSERT, SELECT		Create FARMDB; create crops/plots/seeds; insert first records; SELECT them.Empty farm → plots/crops appear.
2Stock the Farm
INSERT, SELECT columns, multiple rows		Add seeds, fertilizer and feed; insert multiple stock records; display item + quantity.Warehouse fills.
3Find What You Need
WHERE, ORDER BY, LIMIT		Find low-stock seeds; find low-price crops; sort by price; show first 5.Search/report updates.
4Plant & Cleanup
INSERT, UPDATE, DELETE, WHERE		Plant crop in plot; update status/date; correct wrong crop; delete unused seed safely.Plot changes to planted.
5Farm Gets Busy
GROUP BY, COUNT		Count plots used by each crop; identify crops occupying multiple plots.Crop distribution dashboard.
6Farm Statistics
SUM, AVG, MIN, MAX, COUNT		Calculate total stock, average price, cheapest/most expensive crop, crop count.Statistics dashboard.
7Important Crops
HAVING		Show crops with more than 2 plots; compare WHERE with HAVING.Important crops report.
8Smart Filtering
AND, OR, IN, BETWEEN, LIKE		Search by price range/category/name and combine conditions.Advanced search.
9Supply Problem
Suppliers, purchases, dates, CASE		Compare suppliers; total purchases; find expensive purchases; classify prices with CASE.Supplier board.
10Market & Revenue
Customers, products, sales, dates		Find top customers/products; total sales; monthly revenue.Market/revenue dashboard.
11Farm Manager
INNER JOIN		Join employees with plots/crops and show assignments.Workers appear on plots.
12Complete Farm Report
LEFT/RIGHT JOIN, NULL, multiple JOINs, aliases		Find customers with and without orders; build a multi-table report; demonstrate FULL OUTER JOIN concept with LEFT + RIGHT + UNION where needed in MySQL.Management report.
13Above Average
Subquery, correlated subquery		Find crops above average price; compare each record with its own group average using a correlated subquery.Advanced analytics.
14Farm Analysis
CTE / WITH		Build a CTE for production/revenue, then identify high-performing crops or plots.Analyst report.
15Farm Database Design
DDL, PK/FK, relationships, ER, normalization		Alter a table; add/drop a column; rename a table; identify PK/FK; model 1:M and M:M relationships; create/interpret an ER diagram; normalize a badly structured farm table.Professional database design screen.
16Save the Farm with Data
DA Final		Investigate production, customers, no-order customers, monthly revenue, expenses/profit and advanced analysis; produce a data-backed recommendation.DA completes → FARM DATA ANALYST.
17Farm Management View
VIEW		Create a reusable farm sales/reporting VIEW and query it.Manager Reports unlocked.
18Safe Sales
Transactions		Process order + items + stock + payment; COMMIT success; ROLLBACK/SAVEPOINT on failure.Safe checkout.
19Automatic Inventory
TRIGGER		Create a trigger so a sale automatically reduces stock.Inventory updates automatically.
20Farm Automation
Stored procedures		Create a stock-check procedure using parameters, variables and IF/CASE; generate reorder alert.Automation panel.
21Employee Access
GRANT / REVOKE		Set Owner/Manager/Analyst permissions and test restricted operations.Access control.
22Farm Intelligence
AI/data concepts		Analyze historical data for anomalies and simple recommendations; interpret visualization/data-mining results.Farm Intelligence panel.
23The Drought
Full integrated system		Choose crops, plots, suppliers, products, expense cuts, inventory actions and access under limited water/money/land/workers.Full Stack completes → FARM BUSINESS OWNER.

4. Important Design Rule

Common topic = common level/mission. Do not create one DA version and one Full Stack version of the same SQL lesson.

Different requirement = path-specific mission. Full Stack-only concepts begin after the DA final point.

Every mission should produce a database check and, where appropriate, a visible farm consequence. This follows the master plan's Story → Mission → SQL → Database Check → Result Check → Farm Action → Reward flow. fileciteturn4file7
