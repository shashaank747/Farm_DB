🌾 Welcome to FARMDB

Welcome to FARMDB! You are stepping onto a digital agricultural homestead powered by a genuine relational database engine. Rather than learning database concepts purely through abstract lectures or multiple-choice quizzes, you will apply real SQL to solve practical operational problems facing the farm.

During your career, you will use SQL to:

  • Create and manage tables (crops, supplies, animals, plots, facilities)
  • Add and update records (planting schedules, harvest yields, prices)
  • Filter and sort data (low inventory alerts, high-value crops)
  • Analyze agricultural performance (revenue metrics, profit margins)
  • Connect related tables (linking suppliers, orders, and fields)
  • Architect normalized schemas and enforce data integrity
  • Automate workflows with Triggers & Stored Procedures
  • Secure database access with Data Control Language (DCL)
  • Construct AI-assisted decision pipelines and complete the final harvest capstone!

🗄️ What is a Database? Tables, Rows & Columns

A database is an organized, persistent collection of records. Think of a table like a structured spreadsheet:

crop_id (PK) crop_name growth_days market_price
1 Wheat 45 ₹45
2 Rice 60 ₹60
3 Tomato 30 ₹35
  • TABLE: The complete collection of records (e.g., crops).
  • ROW (Record / Tuple): One individual entity row across columns.
  • COLUMN (Field / Attribute): One specific type of information (e.g., crop_name).

🔑 Primary Key (PK) vs 🔗 Foreign Key (FK)

  • PRIMARY KEY: Uniquely identifies each record. "Which exact record is this?"
  • FOREIGN KEY: Connects a row to the primary key of another table. "Which record in another table is this connected to?"
CREATE TABLE crops ( crop_id INT PRIMARY KEY, crop_name VARCHAR(50), market_price FLOAT ); CREATE TABLE farming ( field_id INT PRIMARY KEY, crop_id INT, FOREIGN KEY (crop_id) REFERENCES crops(crop_id) );

🏷️ Common Data Types

  • INT / INTEGER: Whole numbers (e.g., quantity INT)
  • FLOAT / DECIMAL: Fractional numbers (e.g., price FLOAT)
  • VARCHAR(N) / TEXT: Text strings (e.g., crop_name VARCHAR(50))
  • DATE / DATETIME: Calendar dates and timestamps

⚡ Core SQL Commands (CRUD)

1. INSERT — Add New Records

INSERT INTO crops (crop_id, crop_name, market_price) VALUES (1, 'Wheat', 45);

2. SELECT — Retrieve Data

-- Select all columns SELECT * FROM crops; -- Select specific columns (projection) SELECT crop_name, market_price FROM crops;

3. WHERE — Filter Specific Rows

SELECT * FROM crops WHERE market_price > 50;

4. ORDER BY & LIMIT — Sorting & Restricting

-- Sort highest price first and show top 3 SELECT * FROM crops ORDER BY market_price DESC LIMIT 3;

ASC = Ascending (default) | DESC = Descending

5. UPDATE — Modify Existing Data

UPDATE crops SET market_price = 55 WHERE crop_id = 1;

6. DELETE — Remove Outdated Data

DELETE FROM crops WHERE crop_id = 3;

⚠️ Always specify a WHERE clause with UPDATE and DELETE to prevent modifying or deleting the entire table!

📈 Aggregations, Filtering, Joins & NULL

Aggregate Functions

Calculate summary numbers across rows: COUNT(), SUM(), AVG(), MIN(), MAX().

GROUP BY vs HAVING

SELECT crop_id, SUM(quantity) AS total_sold FROM sales GROUP BY crop_id HAVING SUM(quantity) > 100;

Rule: WHERE filters individual rows before grouping; HAVING filters aggregated values after grouping.

Smart Filtering Operators

  • AND / OR: Compound logical conditions
  • BETWEEN 20 AND 50: Value inside inclusive range
  • IN ('Seed', 'Feed', 'Fertilizer'): Value matches any in a list
  • LIKE 'Tom%': Wildcard text pattern matching

Relational JOINs

-- INNER JOIN: returns rows where matches exist in BOTH tables SELECT crops.crop_name, supplies.quantity FROM crops INNER JOIN supplies ON crops.crop_id = supplies.crop_id; -- LEFT JOIN: keeps ALL rows from left table, matching right table (NULL if no match) SELECT crops.crop_name, sales.sale_price FROM crops LEFT JOIN sales ON crops.crop_id = sales.crop_id;

Handling Missing Data (NULL)

Use WHERE phone IS NULL or WHERE phone IS NOT NULL. Never use = NULL.

🏗️ Advanced Queries & Database Architecture

CASE WHEN — Conditional Categorization

SELECT crop_name, CASE WHEN market_price >= 50 THEN 'Premium Crop' ELSE 'Standard Crop' END AS price_category FROM crops;

Subqueries & Common Table Expressions (CTEs)

-- CTE (WITH ... AS) creates modular, reusable intermediate queries: WITH TopSales AS ( SELECT crop_id, SUM(quantity * sale_price) AS revenue FROM sales GROUP BY crop_id ) SELECT crops.crop_name, TopSales.revenue FROM crops INNER JOIN TopSales ON crops.crop_id = TopSales.crop_id WHERE TopSales.revenue > 1000;

Relationships & Normalization

  • 1:1 (One-to-One): One profile per farm entity.
  • 1:M (One-to-Many): One crop variety planted in multiple field plots.
  • M:M (Many-to-Many): Resolved via junction tables with composite primary keys (e.g., crop_suppliers).
  • Normalization (1NF, 2NF, 3NF): Organizing tables to eliminate redundancy and update anomalies.
  • DDL (Data Definition Language): CREATE TABLE, ALTER TABLE ADD COLUMN, RENAME TABLE, DROP TABLE.

🚀 Full Stack Systems (Levels 18–24)

Views (`CREATE VIEW`)

Saved, reusable virtual tables encapsulating complex joins and calculations.

ACID Transactions (`BEGIN`, `COMMIT`, `ROLLBACK`)

Execute multi-step database changes as an all-or-nothing atomic unit to prevent data corruption.

Autonomous Triggers (`CREATE TRIGGER`)

Procedural SQL that fires automatically on INSERT, UPDATE, or DELETE to write audit logs or block invalid data (using BEFORE/AFTER and NEW/OLD).

Stored Procedures (`CREATE PROCEDURE`, `CALL`)

Reusable database subroutines with input parameters (IN) executed with CALL.

Data Control Language (DCL — `GRANT`, `REVOKE`)

Enforce Role-Based Access Control (RBAC) and the Principle of Least Privilege across analysts, managers, and directors.

AI + SQL Ground Truth Pipeline

Relational databases represent immutable ground truth. Structured SQL queries extract precise operational metrics to feed automated AI decision and recommendation engines.

💡 How to Approach Any Mission

  1. Read the story context: Understand the real agricultural situation.
  2. Identify the required data: Which table or columns hold the answer?
  3. Select the right SQL tool: Filter (WHERE), Aggregate (SUM/GROUP BY), Join (INNER JOIN), or Automate (TRIGGER)?
  4. Draft and execute: Type your query and press Ctrl+Enter.
  5. Inspect results: If an error occurs, read the message, check table/column names, check Tier 1–3 hints, and iterate!
